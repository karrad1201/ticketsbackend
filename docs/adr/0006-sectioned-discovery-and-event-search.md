# 0006. Sectioned Discovery And Event Search

## Status

Accepted

## Context

Пользовательский каталог должен быстро отдавать готовые подборки для главной страницы и отдельно поддерживать быстрый текстовый поиск с фильтрами.

Один общий ранжированный список здесь неудобен:

- фронту сложнее собирать экран предложений
- бизнес-правила рекомендаций становятся неявными
- автодополнение по тексту и curated-discovery решают разные задачи

## Decision

- discovery отдаётся отдельным секционным ответом
- ответ содержит массивы:
  - `seenOrganizations`
  - `favoriteCategories`
  - `tomorrow`
  - `dayAfterTomorrow`
- пагинация применяется отдельно к каждой секции
- `size` ограничен значением до `50`
- для сигналов предпочтений вводится внутренняя сущность `UserEventVisit`
- быстрый поиск реализуется отдельным endpoint по названию и фильтрам:
  - `q`
  - `city`
  - `categoryId`
  - `venueId`
  - `dateFrom`
  - `dateTo`

## Consequences

- фронт получает простой ответ-словарь массивов без дополнительной агрегации
- discovery и search можно развивать независимо
- текущая персонализация строится на истории посещений, а не на более сложной ML-логике
