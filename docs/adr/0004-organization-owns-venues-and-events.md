# 0004. Organization Owns Venues And Events

## Status

Accepted

## Context

После появления `Organization` и membership нужно зафиксировать, кому принадлежат каталожные сущности организатора.

Без этого остаются неочевидными два момента:

- кто имеет право создавать `Venue`
- как определить организацию-владельца у `Event`

## Decision

- `Venue` хранит `organizationId`
- `Event` тоже хранит `organizationId`
- при создании `Venue` пользователь обязан передать организацию, в которой он состоит
- use case создания `Venue` проверяет существование организации и membership пользователя
- при создании `Event` организация не передаётся отдельно, а наследуется от `Venue`
- use case создания `Event` проверяет membership пользователя в организации владельца `Venue`

## Consequences

- ownership у каталожных сущностей становится явным
- невозможно создать `Event` с организацией, не совпадающей с `Venue`
- текущая система ролей остаётся простой: для создания достаточно membership, без дополнительного разделения прав
